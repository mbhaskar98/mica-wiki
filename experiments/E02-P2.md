# E02-P2 — Parquet page boundaries across columns

Parent: [[Projects/mica/experiments/Experiments|Mica Experiments Hub]]. Related: [[Projects/mica/mica-plan/E02|E02]].

**Question:** Do columns in our actual Parquet files have the same page counts and row ranges? When a query selects candidate rows, do different columns require different pages?

Parquet row groups cover the same rows across columns, but pages inside them can have different boundaries. Mica row pages share row intervals across columns. We must inspect our files rather than assume that Parquet's boundaries differ. Cold/warm caching does not change the stored boundaries, so this is **one diagnostic test**, not two cache tests.

## Checklist

- [ ] Dump every column's page count, row range, byte offset and size, once per input file.
- [ ] Compare boundaries across columns within every row group; retain concrete matching/mismatching examples.
- [ ] For every requested query, compute candidate row selection once and map those intervals to overlapping pages in its predicate/output columns.
- [ ] Inspect outputs and record whether boundaries differ, and whether those differences affect query candidate-page mappings.

## What is reused and added

| Already exists | Addition |
|---|---|
| `profile_parquet_sync_lazy` binary; Parquet offset indexes; existing query definitions and row-selection helper | Optional `--page-layout-output <directory>` diagnostic mode |
| `exp/run_experiments.py` copying, manifest restoration, cleanup and checkpoints | Separate `parquet-page-layout` test category |

This mode reads metadata and evaluates query candidates. It does not decode query output, measure query latency or run cache thrashing. Candidate-page overlaps are **not** proof of pages actually fetched or decoded. Missing page indexes must be reported as unavailable, not interpreted as aligned columns.

## Run through the existing testbed

In the chosen **Parquet** configuration entries in `exp/experiment_configs.json`, use:

```json
"tests": ["parquet-page-layout"]
```

If retaining other tests, append `"parquet-page-layout"` last. Keep the existing dataset, file locations, manifest and variant settings. Then run from the repository root:

```bash
python3 exp/run_experiments.py --execute
```

The wrapper uses the same data copying and cleanup flow and preserves the original `/data` manifest. It invokes the existing binary's diagnostic mode; no new binary or dataset preparation is required.

| Output under `<batch>/<configuration>/parquet-page-layout/` | Purpose |
|---|---|
| `page-layout.csv` | Per-file, row-group, column and page layout; row ranges and byte locations |
| `query-mapping.csv` | Query candidate intervals and their overlapping column pages |
| `summary.json` | Boundary comparison summary and unavailable/unsupported cases |
