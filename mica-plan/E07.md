# E07 — Is Mica's speed worth its cost?

**Question:** Do Mica's query-time savings justify the time and disk space needed to create and use it?

**Reuse E00–E04:** They cover correctness, page size, indexed alternatives, reader reuse, and queries where Mica wins or loses. Most comparisons are still planned. E07 uses their results when available.

## What E07 adds

| Check | What to do | What it answers | Exists → needed |
|---|---|---|---|
| **1. Creation cost** | Write the same rows in Mica and the strongest E02 alternative. Include indexes. Measure time, CPU, peak memory, temporary disk, and final size. Treat converting existing files and writing new data separately. | Upfront cost of each choice. | Writers and Parquet time/size output exist; Lance builds indexes. Need consistent measurements, including Lance index time/size. |
| **2. Speed versus size** | Use E01 page sizes and supported compression. Compare query time against total file and index size, also under the same disk limit where feasible. | Whether speed requires more disk space. | Compression and query tools exist. Need missing compressed runs and complete size accounting. |
| **3. Unused wide column** | Add a sometimes-long string column; never query it. With and without it, measure writing, page splits, size, and unchanged-column query time. Also test a row too large to write. Use the same inputs in every format. | Whether an unused column makes Mica split the queried columns and slows them. | Mica already splits every column at the same row positions. Need paired inputs and runs. |
| **4. Payback** | Fix a query sequence. Add Mica's wins and losses, including first opens and full reads. Compare with extra creation time; report storage separately. | Whether expected queries repay the extra cost. | E03/E04 specify query measurements. Need their results and the payback calculation. |

**Status:** E07 has not been run.
